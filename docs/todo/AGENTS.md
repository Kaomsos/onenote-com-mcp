# TODO 文档指令

这些规则适用于 `docs/todo/` 中的项目 TODO 台账，并扩展父目录中的文档规则。

## 标识与索引

- [`README.md`](README.md) 是权威 TODO 索引。每个带编号的 TODO 文件必须恰好对应一行索引，且 ID、标题、状态、优先级和路径完全一致。
- TODO 文件命名为 `NNN_<short_slug>.md`。ID 是不可变的三位标识符，新 ID 取当前最大值加一。
- 绝不能重新编号现有 TODO、复用 ID，或仅为了让索引更紧凑而删除已完成或已取消的历史。
- 不得在仓库其他位置放置独立的 `TODO_*.md` 文件；应在此处创建或更新带编号的条目。

## 必需元数据与状态纪律

- 每个 TODO 开头都要显式包含 `ID`、`状态`、`优先级`、`类型` 和 `更新日期` 元数据。
- 标题、状态、优先级、路径或摘要变化时，同时更新文件和索引行。
- 只能使用索引中定义的状态：`待办`、`进行中`、`阻塞`、`已完成` 或 `已取消`。
- 只有在 TODO 声明的完成定义和必需验证均已满足后，才能将工作标记为 `已完成`。如果完成条件需要真实 OneNote 证据，mock 和 dry-run 均不充分；必须记录用户确认。
- 被阻塞或取消的 TODO 必须说明具体原因。保留其决策和证据，供未来读者查阅。

## 内容边界

- TODO 文件跟踪范围、决策、风险、进度和完成证据。将稳定的已实现架构移入 `docs/design/`，将操作指令移入 `docs/dev/` 或相关 README。
- 清单和证据必须如实反映仓库当前状态；不能因为实现仍在规划中或仅部分存在就将条目标记为完成。
